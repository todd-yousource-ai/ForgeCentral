Read Me First

Forge is the platform. ForgeCentral is its console, the web application this guide describes. The Forge engine is the platform's system of record: it holds every configuration, zone, policy, record and decision, and it validates and audits every change. The Forge endpoint agent runs on each protected host and reports what happens there. Everything you configure in ForgeCentral is stored, validated and audited by the Forge engine; ForgeCentral itself keeps no configuration of its own.

Who this guide is for

This guide is for the administrators and security operators who set up and run Forge from ForgeCentral. It covers every configuration ForgeCentral offers: platform settings and change control, identity providers, users and groups, Virtual Trust Zones, objects, policies and their distribution, SOC response, logs and reports, and the actions available from the Overview and the entity drawer.

Installing Forge, the Forge engine and the Forge endpoint agent is outside this guide. Where a value can only be changed on the host (for example a setting the engine reads when it starts), the guide says so and names the setting, so you know who to ask.

How this guide is organized

Chapters 2 and 3 explain how configuration works in Forge and how to move around ForgeCentral. Read them first; every later chapter assumes them. Each configuration chapter then follows the same pattern:

  • Availability: what the chapter covers and whether each part is available, read-only, or not yet available.
  • Concepts and How it works: what the feature does, with a figure whose numbered callouts match the numbered steps below it.
  • Restrictions: limits and known limitations, stated plainly with a workaround where one exists.
  • Configure: one procedure per task, with numbered steps.
  • Verify: how to confirm the change took effect.

Appendix A lists every engine setting ForgeCentral shows, with its default, its bounds and how a change applies. Appendix B collects every known limitation in one place. Appendix C is the glossary.

Availability labels

Every chapter opens with an availability table. The labels mean:

LabelMeaning
AVAILABLEYou can configure it from ForgeCentral today, and the change takes effect as described.
READ-ONLYForgeCentral shows the value and where it comes from, but it is changed somewhere else (usually during installation, on the host).
NOT YET AVAILABLEForgeCentral states that the capability is not built yet, and does not show a control for it.
RECORDED ONLYForgeCentral records the action in the Forge engine, but nothing is enforced on endpoints yet. Forge detects and recommends; enforcement is off.
