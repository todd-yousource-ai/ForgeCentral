Objects

An object gives a name to something a policy can refer to: a user group, a server pattern, a network range, a script, a data store. Policies use objects as their subjects and targets (), so you describe your estate once, by name, and reuse it.

How objects work

An object has a kind (what it is), a selector (how it matches) and a value (what it matches). When you open an object, the Forge engine resolves its value against what it knows right now and lists the matching entities as members. When you use an object in a policy rule, the policy keeps its own copy of the object's selector.

exact matches the value only; glob matches a pattern, such as prod-* or /data/phi/**; cidr matches addresses in a range; group_ref matches the members of a named group.

Restrictions

  • An object's name is unique and cannot be changed after the object is created. The policy form lists an object as kind:name in lower case, for example server:prod-web; the policy list shows the kind and the selector value, for example server:prod-web-*. Two objects with the same selector value appear as one in the policy form.
  • Changing the kind resets the selector to that kind's default; check the selector and value before saving.

Objects you create in ForgeCentral stay drafts: there is no publish action, and policies can still use them. Tags cannot be added from ForgeCentral.

Saving an edit replaces the object's whole record, and clears any attributes the object carried. Check the object's detail after editing an object that had attributes.

A failed delete shows no error message: check that the card has gone.

Create an object

Procedure
  1. Choose Objects, then + Create Object.
  2. Enter a Name, choose the Kind and Selector, and enter the Value (). The value box suggests the format for the kind.
  3. Optionally, enter a Description.
  4. Choose Create Object. The object's card appears under its kind, marked draft.

Edit or delete an object

Procedure
  1. On the object's card, choose Edit, change the kind, selector, value or description, and choose Save.
  2. To delete it, choose Delete on its card and confirm Delete prod-web? with Delete. The object is removed from the catalog; its history remains.
  3. Edit every policy that used the object so its rules pick up the change (a policy holds its own copy).

Verify

  • Find the object with Search objects... (name, value, description or tags) or the Kind filter.
  • Choose the object's name to open it in the entity drawer. Its tags list the selector, the lifecycle, any tags and attributes, and one member= entry for each entity it matches right now (at most 500). No member= entry means nothing matches yet, or the object is an Application, Certificate, Script or Data Store, which have no members in this release.
