Settings: Access and Platform Posture

Six Settings tabs report how the platform is secured and run: RBAC, Security, KeyLock, Observability, HA & Topology and FIPS Mode. They are read-only. Each value is the Forge engine's own report or its configuration, labelled with its source, and each tab says where a value is changed.

RBAC

Settings>RBAC shows two independent lists:

  • Engine admin assignments: the identities the Forge engine itself treats as administrators, each with its roles and clearance. This is boot configuration: the tab states the version it was read from and that it changes on the engine host, followed by an engine restart.
  • Console operator roles: ForgeCentral's role map, which turns your identity-provider groups (or, failing a group, your identity itself) into a ForgeCentral role, and names the default tenant for global administrators. It is read when ForgeCentral starts and changes only when ForgeCentral is reinstalled. Only global administrators can see it, because it names every tenant it grants.

Roles are resolved from your identity-provider groups first; the highest role wins. The per-identity grants apply only when your sign-in carries no group.

The ForgeCentral installer writes a role map with one global administrator and no group grants, and reinstalling rewrites the map. Granting a group a role requires editing the installation settings, and the edit is lost on the next install unless it is carried into the installer's inputs.

Security

Your browser reaches the Forge engine over two protected connections (). The Security tab reports on the first, and on the engine's own administration endpoint:

  1. This browser session shows the key exchange your browser negotiated with ForgeCentral: the hybrid post-quantum group when your browser supports it, otherwise the P-384 floor. ForgeCentral refuses a browser that offers neither, rather than downgrading.
  2. Admin endpoint is the engine's connectivity report for its administration listener: the listen address, whether mutual TLS is required, how many administrator identities are bound, and whether the post-quantum hybrid key exchange is offered. ForgeCentral does not use this endpoint; the mutual-TLS and post-quantum rows state the engine's built-in posture rather than a measurement.

The Security tab does not report on connection 2, from ForgeCentral to the Forge engine.

The tab also shows Server security, the engine's security report: its operating classification, the audit chain (Verified or Failed verification), the number of audit entries and the head version, and how many stored artifacts were spot-checked and how many failed. The engine verifies the audit chain when you open the tab. Registered egress destinations lists where the engine may send data for model inference, with each destination's classification ceiling; you add and remove them on Settings>Configuration.

Failed verification on the audit chain means the engine's audit record does not verify. Treat it as a security incident: do not change configuration, and contact security@yousource.ai.

If This browser session reads Not available, the session lookup was not set up when ForgeCentral was installed; reinstall ForgeCentral to enable it. The tab also says key issuing is edited on Configuration; it is not editable in this release.

KeyLock

Agent key issuing reports whether the engine issues keys to agents, whether enrolling, issuing, rotating and revoking a key needs two people, and how long an issued key is valid. Signing-key rotation is not available in this release: there is no rotate control, and the signing key ids are not shown.

Observability

Telemetry ingest is the engine's telemetry report: whether its OpenTelemetry (OTLP) receiver is running, its gRPC and HTTP addresses, the ingest queue capacity, and how many tenants are bound. Below it, Observability settings mirrors the two observability rows of the governed configuration; the ingest byte budget per window is edited on Settings>Configuration (surface observability). The telemetry exporter is configured at boot and is not shown.

HA & Topology

This node is the engine's server report: shards hosted, whether it is serving, whether storage is durable, the maintenance cadence, the administration frame ceiling and the engine version. Multi-node cluster views, leadership rotation, quorum-loss tests, disaster-recovery targets and failover tests are not available in this release.

The maintenance cadence shown here is the value the engine started with. After you change maintenance.cadence_secs on Configuration, the new cadence is in force but this report shows the old value until the engine restarts.

FIPS Mode

Crypto build posture shows the cryptographic provider and whether the FIPS-validated module is linked. FIPS mode is chosen when the engine is built; it cannot be switched on a running node, so the tab has no toggle.
