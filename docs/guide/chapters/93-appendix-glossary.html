Glossary

Terms

TermMeaning
Anchor keyThe public key installed on an endpoint that it uses to verify a distributed policy bundle's signature.
Audit trailThe engine's tamper-evident record of changes: who did what, when. An incident also has its own trail of actions.
Boot configurationValues the Forge engine reads when it starts. Changed on the engine host, then an engine restart.
BundleA zone's published policies, composed and signed for distribution to endpoints.
CalibrationA fit, from real dispositions, that turns the engine's credibility score into a probability that an incident is real. Until one exists, incidents are uncalibrated.
ClassificationA data sensitivity level: unclassified, internal, confidential, restricted, secret.
CredibilityThe engine's score for how well a detection is supported by evidence.
DecisionOne governed outcome the engine recorded from detection; listed on Logs.
DispositionAn analyst's verdict that closes an incident and teaches calibration what it was.
Dual control (two-person control)A rule that a change proposed by one administrator must be approved by another.
Effective postureA zone's restrictions after combining its own with every ancestor's; a restriction anywhere wins.
Egress destinationA place the engine may send data for model inference, with the highest classification it may receive.
EnforcementBlocking activity on an endpoint. Off in this release: Forge detects, records and recommends.
Entity drawerForgeCentral's detail panel for a user, agent, host or object.
Fixed floorThe two restrictions no zone can relax: governed egress and execution.
ForgeThe platform: detection, governance and response for users, hosts and AI agents.
Forge endpoint agentThe software on each protected host that reports activity to Forge and fetches distributed policy.
Forge engineThe platform's system of record: it stores, validates and audits every configuration, record and decision.
ForgeCentralThe Forge console, the web application this guide describes.
Governed configurationThe Forge engine's versioned settings document, changed on Settings.
Identity provider (IdP)Your organization's directory and sign-in service, such as Auth0.
IncidentA detection the engine promoted for an analyst's attention; worked on SOC Ops.
LeaseThe freshness window stamped on a distributed bundle; an endpoint refuses a bundle whose lease has expired.
Local user graph (LUG)The Forge user directory's view of the accounts, groups and sessions on each host.
Mutual TLSAn encrypted connection in which both sides prove their identity with certificates.
ObjectA named thing a policy can refer to: a group, server pattern, network range and so on.
PolicyWhat subjects may do to targets in one zone, with one action, versioned and published.
Post-quantum hybrid key exchangeA key exchange (X25519MLKEM768) designed to stay secure against future quantum computers, combined with a classical one. P-384 is the classical floor used when a browser lacks it.
PrincipalAn identity the engine authorizes: a person, service account or AI agent. Its id is shown in the Users ID column.
ProposalA Settings change waiting for a second administrator's approval.
Response planThe steps the engine proposes for an incident, within its response tier.
Response tierNoise, investigate or propose: what the engine may put forward for an incident, decided by p_low and p_high.
SelectorHow an object matches: exact, glob, cidr or group_ref.
SIEMSecurity information and event management system, such as Splunk or Microsoft Sentinel.
TenantAn isolated customer or organizational unit within a Forge node.
Virtual Trust Zone (VTZ)A named place in a hierarchy that policies target; it inherits and can only tighten its ancestors' restrictions.
